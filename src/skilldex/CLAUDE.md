# src/skilldex/ — Skilldex

Interactive talent-tree visualizer: every talent as a small D3 tree, with prerequisite tracking, requirement/tier/card-set filters and formatting options. Talent data comes from Supabase — the only Supabase read in the app (`src/shared/CLAUDE.md` covers why cards don't).

## Key files

- `index.tsx` — the feature entry
- `components/TalentResultsPanel/TalentTree/` — the tree component (layout memo, draw effect, zoom effect); node drawing in `talentNodes.ts` / `requirementNodes.ts`, sizing in `utils/talentNodeDimensions.ts`
- `hooks/useSearchFilters/` — Skilldex's filter groups and `talentTreeFilter.ts`, which is concrete/talent-specific by design; don't re-generalize for one consumer. The framework and the card-set group shared with Cardex are in `src/shared/hooks/useSearchFilters/`
- `hooks/useTalentData.ts` → `services/talentsApiSupabase.ts` → `utils/talentsResponseMapper.ts`, cached 24h by `utils/talentsStore.ts`. `supabase/functions/README.md` covers what to change here when the talents sync brings new card sets or tiers

## Invariants

- **The tree infrastructure, zoom and filter-framework invariants live in `src/shared/CLAUDE.md`** — notably the layout/render split, which `TalentTree` must follow, and the nil-expansion rule, whose render half lives in `TalentTree` (`shouldShowCardSet` and `getCardSetName` must agree).
- **Talent artwork is flush with the node's left edge, fills the name row's height, and is `WIDTH_SCALE` times as wide** — the square 70×70 source is scaled to cover that wider window with `slice`, so only its middle horizontal band shows. Widening trades vertical crop for horizontal coverage, _not_ resolution: at `WIDTH_SCALE: 1.5` the scale is ~1.0× and ~67% of the source's height is visible. **Artwork does change node height**, via `NODE.ARTWORK.EXTRA_ROW_HEIGHT` added to the name row — which is why `getNameRowHeight` in `talentNodeDimensions.ts` is shared by the dimension engine _and_ the renderer rather than duplicated. Changing that dial is safe precisely because both paths read the one function; writing the sum out twice is what the nil-card-set invariant warns against.
- **The name's layout ignores `WIDTH_SCALE` on purpose.** It's centred in the space beside a _square_ artwork, so widening never moves the text — the wider art passes underneath and a `<linearGradient>` mask (`FADE_WIDTH`) fades it out before it reaches the glyphs. Recentring the name against the widened art instead would squeeze long names and push them off-centre. The placeholder square is deliberately **not** masked: a faded flat rect reads as a rendering glitch where a crisp one reads as "no art".
- **The flush-left artwork clips to `NODE.CORNER_RADIUS`, which must match `.talent-node`'s `rx`/`ry`.** Flush on two edges means the square art overlaps the node's rounded corners, so it's clipped to a hand-built path (`roundedLeftEdgePath`) rather than `rx`/`ry` — only the _left_ corners round, and only when the name row is the node's first/last row. The bottom-left case is live: with description, Blightbane link and additional requirements all absent, the name row **is** the whole node. Corner flags are computed in `renderTalentNode`, which is the only place that knows what sits below the name row. Nothing type-checks the radius against the stylesheet; both sides carry a comment.
- **Positioning anything beside `.talent-node-name` requires _measuring_ the name.** It's SVG `text` with `text-anchor: middle`, so D3 reports no width and a guessed offset silently overlaps the glyphs (exactly how the first artwork attempt broke). `talentTextMeasurer.ts` has variants matching the name's three font states (`name` / `nameCollapsed` / `nameCollapsedLong`) — **those must stay in sync with `.talent-node-name`'s font sizes and weight in the stylesheet**. The name is centred in the space _remaining_ beside the icon, not on the node, and truncated with `truncateTalentName` (SVG `text` has no `text-overflow: ellipsis`) at `NODE.ARTWORK.NAME_MAX_WIDTH_RATIO` of that space.
- **Talent artwork has no higher-resolution source than 70×70.** Probed `images/cards/`, `images/large/`, `images/full/`, `images/icons_large/`, `images/cards_full/` and `.png`: all return the same 3826-byte placeholder with HTTP 200 (a deliberately bogus filename does too), and the `.png` is the same 70×70 at 4× the bytes. A full-width 200px strip was tried first and looked visibly pixelated at that 2.9× upscale — so the name row's height doubles as the crispness ceiling, and displaying talent art much larger anywhere will look soft no matter how it's fetched. A talent missing from the mapping draws the flat placeholder square, so the name's position never depends on whether the mapping resolved.
- Tree layout/rendering changes are verified **visually** (before/after comparison in the dev server, incl. expanded/collapsed nodes and zoom levels), not with unit tests. The **user** runs the dev server and does the comparison — don't start one yourself; say what changed and which states to look at (see Working Style in the root `CLAUDE.md`).
