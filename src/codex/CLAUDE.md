# src/codex/ — Cardex and Skilldex

This directory hosts two tools: **Cardex** (`cards.tsx`) and **Skilldex** (`skills.tsx`), sharing `components/`, `hooks/`, `utils/`, and `types/`. Code used by more than one of them has moved to `src/shared/` (see its `CLAUDE.md`), ahead of each tool getting its own folder (`src/specs/split-codex.md`). Booty and Eventmaps have already moved to `src/booty/` and `src/eventmaps/`.

## Key files

- `components/SearchPanels/` + `components/ResultsPanels/` — per-tool search UI and result rendering (incl. `TalentTree`)
- `hooks/useSearchFilters/` — filter state + filtering logic (`talentTreeFilter.ts` is concrete/talent-specific by design; don't re-generalize for one consumer). the shared framework and `useCardSetFilters.ts` (which exports **two** hooks — see the nil-expansion invariant) live in `src/shared/hooks/useSearchFilters/`

## Invariants

- **Invariants for code shared between the tools** — trees and zoom, the filter framework and URL codes, the card data layer and artwork lookup — **live in `src/shared/CLAUDE.md`**, next to that code.
- **Talent artwork is flush with the node's left edge, fills the name row's height, and is `WIDTH_SCALE` times as wide** — the square 70×70 source is scaled to cover that wider window with `slice`, so only its middle horizontal band shows. Widening trades vertical crop for horizontal coverage, _not_ resolution: at `WIDTH_SCALE: 1.5` the scale is ~1.0× and ~67% of the source's height is visible. **Artwork does change node height**, via `NODE.ARTWORK.EXTRA_ROW_HEIGHT` added to the name row — which is why `getNameRowHeight` in `talentNodeDimensions.ts` is shared by the dimension engine _and_ the renderer rather than duplicated. Changing that dial is safe precisely because both paths read the one function; writing the sum out twice is what the nil-card-set invariant warns against.
- **The name's layout ignores `WIDTH_SCALE` on purpose.** It's centred in the space beside a _square_ artwork, so widening never moves the text — the wider art passes underneath and a `<linearGradient>` mask (`FADE_WIDTH`) fades it out before it reaches the glyphs. Recentring the name against the widened art instead would squeeze long names and push them off-centre. The placeholder square is deliberately **not** masked: a faded flat rect reads as a rendering glitch where a crisp one reads as "no art".
- **The flush-left artwork clips to `NODE.CORNER_RADIUS`, which must match `.talent-node`'s `rx`/`ry`.** Flush on two edges means the square art overlaps the node's rounded corners, so it's clipped to a hand-built path (`roundedLeftEdgePath`) rather than `rx`/`ry` — only the _left_ corners round, and only when the name row is the node's first/last row. The bottom-left case is live: with description, Blightbane link and additional requirements all absent, the name row **is** the whole node. Corner flags are computed in `renderTalentNode`, which is the only place that knows what sits below the name row. Nothing type-checks the radius against the stylesheet; both sides carry a comment.
- **Positioning anything beside `.talent-node-name` requires _measuring_ the name.** It's SVG `text` with `text-anchor: middle`, so D3 reports no width and a guessed offset silently overlaps the glyphs (exactly how the first artwork attempt broke). `talentTextMeasurer.ts` has variants matching the name's three font states (`name` / `nameCollapsed` / `nameCollapsedLong`) — **those must stay in sync with `.talent-node-name`'s font sizes and weight in the stylesheet**. The name is centred in the space _remaining_ beside the icon, not on the node, and truncated with `truncateTalentName` (SVG `text` has no `text-overflow: ellipsis`) at `NODE.ARTWORK.NAME_MAX_WIDTH_RATIO` of that space.
- **Talent artwork has no higher-resolution source than 70×70.** Probed `images/cards/`, `images/large/`, `images/full/`, `images/icons_large/`, `images/cards_full/` and `.png`: all return the same 3826-byte placeholder with HTTP 200 (a deliberately bogus filename does too), and the `.png` is the same 70×70 at 4× the bytes. A full-width 200px strip was tried first and looked visibly pixelated at that 2.9× upscale — so the name row's height doubles as the crispness ceiling, and displaying talent art much larger anywhere will look soft no matter how it's fetched. A talent missing from the mapping draws the flat placeholder square, so the name's position never depends on whether the mapping resolved.
- **Monster cards are rarity 4 / banner 11 — _not_ card type 7.** Cardex treats monster cards as one opt-in population behind the single _Include Monster cards_ checkbox in Extras, so every filter group whose `indexMap` can address them must defer to `shouldIncludeMonsterCards` for them (see `isCardMatching` in `useAllCardSearchFilters.ts`). Rarity and banner get this for free — indices 4 and 11 are absent from their `indexMap`s, so nothing can select them. **Card type is the dangerous case**: ~1000 monster cards carry an ordinary type (mostly Utility), all of which _are_ selectable, so keying the deferral on the card's type instead of on the card lets the Type group silently veto monster cards the user opted into. Type 7 invites exactly that mistake — it looks like a monster marker but sits on only ~10 cards, one of which (`Infernal Racket`) `getActualColor` deliberately remaps to a normal banner. It has no checkbox, and stays in `indexToValueMap` only so those cards render a label. Verify changes here against the live `cards-codex` payload rather than by eye: the failure mode is one filter combination over ~1000 cards.
- **`.result-card` rows carry `content-visibility: auto`, and `contain-intrinsic-size` must stay with it.** The property lets the browser skip style, layout and paint for off-screen rows — it cut Rendering + Painting 42% on a filter toggle (904ms → 524ms), which is the whole reason Cardex is _not_ virtualized (`src/specs/inp.md` Part 1 records the measurements and why Tasks 2–6 were dropped). Two consequences. First, dropping `contain-intrinsic-size` makes skipped rows report zero height and the scrollbar jump as they render on scroll; `auto <height>` is what lets the browser keep each row's real height once measured, so the literal only matters before a row has ever been on screen. Second, `content-visibility: auto` implies **`contain: layout paint`** on every row, so anything that deliberately paints outside a row's border box is at risk — the row's hover, struck and full-match backgrounds now sit entirely inside it (the row owns its horizontal padding, so nothing has to bleed outwards), but a new overflowing decoration (an outer glow, a badge hanging off the edge) would be clipped with no error. Verify such changes visually rather than assuming. Rows stay in the DOM, so Ctrl-F still finds off-screen ones — unlike virtualization, which is the trade this approach exists to avoid.
- **`.result-card__name`'s widths are minimums, not fixed sizes.** Its `flex-shrink: 1` + `min-width: 0` are what let the `CardMetadata` pill stay pinned to the right edge of the title row on narrow widths — the pill is `flex-shrink: 0`, so the name is the only element that can give. Restoring hard widths there pushes the pill off the edge or overflows the row on mobile.
- Tree layout/rendering changes are verified **visually** (before/after comparison in the dev server, incl. expanded/collapsed nodes and zoom levels), not with unit tests. The **user** runs the dev server and does the comparison — don't start one yourself; say what changed and which states to look at (see Working Style in the root `CLAUDE.md`).
