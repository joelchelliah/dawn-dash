# src/codex/ — Cardex

This directory hosts **Cardex** (`cards.tsx`), the last tool still to move out of `src/codex/` (`src/specs/split-codex.md`). Code it shares with other tools is in `src/shared/` (see its `CLAUDE.md`).

## Key files

- `components/SearchPanels/CardSearchPanel/` + `components/ResultsPanels/CardResultsPanel/` — search UI and result rendering
- `hooks/useSearchFilters/` — Cardex's filter groups and `useAllCardSearchFilters`; the shared framework and `useCardSetFilters.ts` (which exports **two** hooks — see the nil-expansion invariant) live in `src/shared/hooks/useSearchFilters/`

## Invariants

- **Invariants for code shared between the tools** — trees and zoom, the filter framework and URL codes, the card data layer and artwork lookup — **live in `src/shared/CLAUDE.md`**, next to that code.
- **Monster cards are rarity 4 / banner 11 — _not_ card type 7.** Cardex treats monster cards as one opt-in population behind the single _Include Monster cards_ checkbox in Extras, so every filter group whose `indexMap` can address them must defer to `shouldIncludeMonsterCards` for them (see `isCardMatching` in `useAllCardSearchFilters.ts`). Rarity and banner get this for free — indices 4 and 11 are absent from their `indexMap`s, so nothing can select them. **Card type is the dangerous case**: ~1000 monster cards carry an ordinary type (mostly Utility), all of which _are_ selectable, so keying the deferral on the card's type instead of on the card lets the Type group silently veto monster cards the user opted into. Type 7 invites exactly that mistake — it looks like a monster marker but sits on only ~10 cards, one of which (`Infernal Racket`) `getActualColor` deliberately remaps to a normal banner. It has no checkbox, and stays in `indexToValueMap` only so those cards render a label. Verify changes here against the live `cards-codex` payload rather than by eye: the failure mode is one filter combination over ~1000 cards.
- **`.result-card` rows carry `content-visibility: auto`, and `contain-intrinsic-size` must stay with it.** The property lets the browser skip style, layout and paint for off-screen rows — it cut Rendering + Painting 42% on a filter toggle (904ms → 524ms), which is the whole reason Cardex is _not_ virtualized (`src/specs/inp.md` Part 1 records the measurements and why Tasks 2–6 were dropped). Two consequences. First, dropping `contain-intrinsic-size` makes skipped rows report zero height and the scrollbar jump as they render on scroll; `auto <height>` is what lets the browser keep each row's real height once measured, so the literal only matters before a row has ever been on screen. Second, `content-visibility: auto` implies **`contain: layout paint`** on every row, so anything that deliberately paints outside a row's border box is at risk — the row's hover, struck and full-match backgrounds now sit entirely inside it (the row owns its horizontal padding, so nothing has to bleed outwards), but a new overflowing decoration (an outer glow, a badge hanging off the edge) would be clipped with no error. Verify such changes visually rather than assuming. Rows stay in the DOM, so Ctrl-F still finds off-screen ones — unlike virtualization, which is the trade this approach exists to avoid.
- **`.result-card__name`'s widths are minimums, not fixed sizes.** Its `flex-shrink: 1` + `min-width: 0` are what let the `CardMetadata` pill stay pinned to the right edge of the title row on narrow widths — the pill is `flex-shrink: 0`, so the name is the only element that can give. Restoring hard widths there pushes the pill off the edge or overflows the row on mobile.
