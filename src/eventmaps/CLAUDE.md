# src/eventmaps/ — Eventmaps

Fully mapped event trees (branches, requirements, rewards), one per event, rendered with D3 from the static `src/shared/data/event-trees.json` (shared with Booty; regenerated by `scripts/sync/sync-events.js`, never hand-edited — see `scripts/parse/README.md` for the pipeline).

## Key files

- `index.tsx` — the feature entry; `pages/eventmaps/index.tsx` and `pages/eventmaps/[event].tsx` both render it, the latter with a statically generated `<head>` per event
- `components/EventResultsPanel/EventTree/` — the tree component (layout memo, draw effect, zoom effect)
- `utils/eventTreeSpacing/` — event-tree layout: `d3-flextree` (variable-width tidy layout) + a multi-parent centering pass for refChildren, plus the vertical spacing pass; read its `README.md` before touching it

## Invariants

- **The tree infrastructure, zoom and filter-framework invariants live in `src/shared/CLAUDE.md`** — notably the layout/render split, which `EventTree` must follow, and zoom committing on drag end.
- **`requirements` render on `choice`, `result`, `dialogue` _and_ `end` nodes** — `isRequirementsNode` in `eventNodeDimensions.ts` gates both the width calculation and the box height, and `renderTextNodeContent` draws the box for the text-node types. Dialogue/end nodes carry requirements when a `[?condition]` conditional in the Ink gates that line (see the conditional-variant section of `scripts/parse/README.md`), and the parser's engine-test shape depends on them being visible: narrowing the guard back to choice/result would silently hide 21 nodes' conditions rather than fail. The dimension helper and the renderer must agree on the box's place in the vertical stack (text → effects → requirements → continues → loop), or nodes reserve height for a box drawn elsewhere.
- **`pages/eventmaps/` doesn't share one page component the way `pages/booty/` does**, so moving between events remounts the whole tree and discards the layout memo, the filters and the zoom level. See the Booty route invariant in `src/booty/CLAUDE.md` for the fix if that ever matters.
- Tree layout/rendering changes are verified **visually** (before/after comparison in the dev server, incl. expanded/collapsed nodes and zoom levels), not with unit tests. The **user** runs the dev server and does the comparison — don't start one yourself; say what changed and which states to look at (see Working Style in the root `CLAUDE.md`).
